# 0003 · 내용 주소 저장과 정규화 해시

- 상태: 채택
- 범위: orchestrator, 서비스 사이 계약

## 맥락

기획서의 모든 값은 어느 서비스의 어느 응답에서 왔는지 따라갈 수 있어야 한다. 응답을 고쳐 쓰거나 다시 만든 값이
원문인 척하면 근거 추적이 무너진다. 서비스가 서로 다른 언어 습관으로 JSON을 직렬화해도 같은 값은 같은 해시여야 했다.

## 결정

- 바이트(응답 원문, 호출 요청, 이미지, 기획서 PNG)는 SHA-256을 이름으로 저장하고 `artifact://orchestrator/blobs/<sha256>`로
  가리킨다. 참조에는 크기와 해시를 함께 적는다.
- JSON 값은 `python-json-sort` 규칙(키 정렬, 공백 없는 구분자, UTF-8, NaN 금지)의 SHA-256으로 식별한다
  ([contracts.md](../contracts.md#4-해시-python-json-sort)).
- 다른 서비스의 산출물은 읽기 전용 마운트에서 크기와 해시를 확인한 뒤에만 가져온다.

## 결과

- 결합 검사가 "novelty가 실제로 받은 요청"과 "저장된 trend·inventory 원문"을 해시로 대조할 수 있다.
- 같은 바이트는 한 번만 저장된다.
- 해시는 바이트가 같다는 것을 증명할 뿐, 문장이 사실이라는 것을 증명하지 않는다. 사실 여부는 근거 ID와 MD 검토가 맡는다.

## 검토한 대안

| 대안 | 택하지 않은 이유 |
|---|---|
| 응답을 정규화한 뒤 저장 | 원문이 사라져, 서비스가 무엇을 보냈는지 나중에 확인할 수 없다 |
| 실행 ID와 순번으로 이름 짓기 | 같은 내용이 여러 번 저장되고, 이름만으로 내용이 바뀌었는지 알 수 없다 |
