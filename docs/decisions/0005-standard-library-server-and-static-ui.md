# 0005 · 표준 라이브러리 HTTP 서버, 정적 UI, 결정적 기획서

- 상태: 채택
- 범위: orchestrator

## 맥락

orchestrator의 HTTP 표면은 작고(경로 표 하나), 로컬이나 사설 네트워크에서만 쓴다. UI는 한 사람의 MD가 실행을 따라가는
작업 화면이고, 결과물인 기획서는 같은 실행에서 늘 같은 그림이 나와야 검토와 비교가 쉽다.

## 결정

- HTTP는 표준 라이브러리 `http.server`로 만든다. 경로는 명시적 표로만 연결하고, 기본 바인드는 loopback이며, 다른 주소는
  `ORCHESTRATOR_ALLOW_REMOTE_BIND=1`과 신뢰 목록(상대 주소, Host, Origin)이 있어야 받는다.
- UI는 빌드 단계 없는 정적 ES 모듈이다. 화면 계산 규칙은 `web/js/model.js`에 모으고 node 테스트로 확인한다.
- 6단계 기획서는 Pillow로 실행 기록만 읽어 결정적으로 그린다. 이미지 모델은 부르지 않는다. 상품·착장 이미지는 novelty가
  만들고, orchestrator는 그 이미지와 실행 기록을 배치한다.

## 결과

- 오케스트레이션 핵심은 서드파티 의존성이 없다(계약 검증·기획서·질의 구조화만 extra).
- `http.server`는 인터넷에 직접 노출할 서버가 아니다. 공개 서비스로 쓰려면 앞에 단단한 서버를 두거나 프레임워크로 바꿔야 한다.
- 기획서 다시 그리기는 비용이 없고 네트워크도 쓰지 않는다. 같은 실행이면 같은 PNG가 나온다.

## 검토한 대안

| 대안 | 택하지 않은 이유 |
|---|---|
| FastAPI 같은 웹 프레임워크 | 경로가 적고 동기 처리라 얻는 것이 적다. 의존성과 배포 표면이 늘어난다 |
| React·Vue 같은 SPA 빌드 | 화면 상태가 단순하다. 빌드 도구 없이 바로 서빙하는 쪽이 재현과 검토가 쉽다 |
| 이미지 모델로 기획서 생성 | 같은 입력에서 다른 그림이 나오고, 표시된 값이 실행 기록과 같다는 보장이 없다. 비용도 든다 |
