# 0004 · 동결된 계약 기준선이 있을 때만 실행

- 상태: 채택
- 범위: orchestrator

## 맥락

다섯 레포가 각자 바뀌는 동안, 서로 맞지 않는 계약으로 실행해 놓고 결과를 정상처럼 쓰는 일을 막아야 했다. 계약 사본을
작업 중인(커밋하지 않은) 트리에서 만든 적이 있어, 기록된 출처를 다시 만들 수 없었던 경험도 있다.

## 결정

- 호출 쪽 스키마의 바이트를 `contracts/workflow/snapshot.json`에 SHA-256으로 고정한다.
- `contracts/workflow/baseline.json`이 `frozen`이고 스냅샷과 파일이 일치할 때만 워크플로를 실행한다. 아니면
  `409 CONTRACT_NOT_FROZEN`이다.
- 동결은 `scripts/freeze_workflow_contract.py --freeze`로만 한다. 참조 fixture, 변형 프로브, 함께 지정한 테스트가 모두
  통과하고 다섯 레포가 깨끗한 checkout일 때만 쓴다. 기록에는 브랜치·커밋 대신 checkout 내용의 해시를 남긴다.
- 개발 중에는 `ORCHESTRATOR_WORKFLOW_ALLOW_PROPOSED=1`로 실행할 수 있고, 그 결과에는 개발 실행이라는 한계가 붙는다.

## 결과

- 계약이 바뀌면 기준선을 다시 동결하기 전까지 운영 실행이 멈춘다. 의도한 마찰이다.
- 동결 증거는 계약 수준의 증거(오프라인 fixture, 직렬화·파싱 경계)일 뿐, 실제 데이터의 품질이나 모델 성능을 뜻하지 않는다.

## 검토한 대안

| 대안 | 택하지 않은 이유 |
|---|---|
| 런타임 스키마 검증만 | 개별 응답은 막지만, 계약 파일 자체가 바뀐 것을 실행 전에 알 수 없다 |
| 버전 번호 비교 | 번호를 올리지 않은 변경을 놓친다. 바이트 해시는 놓치지 않는다 |
